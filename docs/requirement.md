# 底部导航栏（Tab Bar）

## 设计原则

本 App 的核心定位为：

**Dance Practice Platform（扒舞练习平台）**

用户打开 App 的主要目的：

* 创建练习室
* 练习舞蹈
* 查看练习数据
* 管理个人练习记录

因此导航栏应围绕「练习」而非「内容消费」设计。

=====登录功能======

目标：
支持云同步、练习数据统计、多设备同步。

账号功能：
- 注册账号
- 登录账号
- 忘记密码（后续）
- 邮箱验证（后续）

游客模式：
- 允许游客使用 App
- 游客可创建练习室
- 游客可上传本地视频
- 游客可使用所有扒舞功能
  - 倍速
  - 镜面
  - A-B 循环
  - 缩略图进度条

数据存储策略：

账号用户：
- 数据存储在云端数据库
- 支持多设备同步
- 支持练习时长统计
- 支持练习历史记录

游客用户：
- 数据仅保存在本机
- 不同步到云端
- 卸载 App 后数据可能丢失

游客转账号：

场景：
游客创建练习室后注册账号

处理方式：
登录成功后提示：

"检测到本机存在游客数据，是否导入当前账号？"

用户可选择：
- 导入
- 忽略

导入内容：
- 练习室
- 视频信息
- A-B 循环片段
- 练习记录
- 视频设置（镜面、倍速等）

同步规则：

账号数据 与 游客数据 完全隔离。

游客 CRUD：
- 只影响本地游客数据

账号 CRUD：
- 只影响当前账号数据

游客数据不会自动修改账号数据。

只有用户主动点击："导入到当前账号"，才会发生数据迁移。

删除规则：
游客删除：
- 仅删除本地游客数据

账号删除：
- 删除账号云端数据

游客数据导入账号时：
- 支持新增（Create）
- 支持更新（Update）
- 不自动执行删除（Delete）

避免误删用户云端数据。

======扒舞核心功能===================================

1. 视频播放

支持用户上传/导入原舞蹈视频。上传的时候用户可以先裁剪视频

2. 倍速控制

至少支持：

0.25x / 0.5x / 0.75x / 1x / 1.25x

做成变速条，而不是只能选特定的速度

3. 镜面模式

一键水平翻转视频。

4. A-B 循环

用户设置：

A 点开始时间
B 点结束时间
播放到 B 自动回 A

5. 逐帧缩略图进度条

这个是你的亮点功能。

进度条下面不是普通一条线，而是一排视频缩略帧：

| frame | frame | frame | frame | frame |

用户不用乱拖，可以直接看到副歌、动作变化、队形变化在哪里。


6. 双屏对比

左边：原视频
右边：用户自己的练习视频
